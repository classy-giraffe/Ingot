## Destination

The way to a conforming Ingot core is clear: every open decision in `docs/SPECS.md` that gates the 15 Section-25 acceptance criteria plus the server profile is resolved and recorded on this map, and the map collapses into `/to-spec` as a buildable plan. This map produces decisions, not deliverables - the build happens after the handoff.

## Notes

- Domain: immutable, systemd-first, x86_64 UEFI Linux OS (Ingot). Canonical design reference: `docs/SPECS.md` (Draft 1.0, normative). Tickets resolve its open items; a resolution is a decision recorded on the ticket and gisted here.
- Skills every session should consult: `grilling` + `domain-modeling` (the default pair for grilling tickets), `research` (for research tickets), and `docs/agents/*.md` for tracker conventions.
- Standing preferences: plan, don't do (no deliverables from this map). Workstation profile drives the first buildable slice. No paid hosting (no S3/CDN) - GitHub Releases is the only release infrastructure. Rust userland is built from pinned upstream source, never from distro packages.
- Tracker: GitHub (`classy-giraffe/Ingot`); conventions in `docs/agents/issue-tracker.md`.

## Decisions so far

- [Research: Fedora Rawhide base feasibility](https://github.com/classy-giraffe/Ingot/issues/11): feasible, no show-stopper - fc46 carries everything needed (systemd 262~rc3 tool reorg, kernel 7.3.0-rc UKI+EROFs, rust 1.98.1); mkosi pins via `Snapshot=`; brush/zellij unbundled (source build, dynamic glibc); pinned compose must be archived. Findings on `research/fedora-rawhide-base`.
- [Research: systemd-sysupdate transfer capabilities](https://github.com/classy-giraffe/Ingot/issues/12): workable with v261.3 - plain HTTPS asset URLs work as `Path=`, no `url-directory` exists, `latest` is version-sorted from `SHA256SUMS` (manifest.json never parsed), GPG+SHA256 verify on URL sources, versioned entries + tries counters CONFLICT with the spec's fixed slot-a/b UKI names. Narrow helper needed (manifest latest + auth). Findings on `research/sysupdate-transfer`.
- [Lock the base distro and Rust build strategy (Fedora Rawhide, cargo-built Rust userland)](https://github.com/classy-giraffe/Ingot/issues/2): locked - Fedora Rawhide (fc46) pinned per Ingot release via `Snapshot=` (bump is a deliberate recorded act; pinned compose archived to self-hosted storage, public mirror retains ~1 week); all five Rust components source-built from pinned upstream via cargo in prepare (no distro packages); pins = release tag + resolved commit SHA in an in-repo manifest; brush dynamic against image glibc as `/bin/sh`; static dash as initramfs shell (new OPTIONAL component); systemd components installed by capability (v262 subpackage reorg); distro kernel accepted (compose pin is the kernel floor, 7.3.0-rc3 at pin time).
- [Lock the slot payload model (/usr-only slots, minimal runtime root)](https://github.com/classy-giraffe/Ingot/issues/3): locked - slot = exactly the `/usr` tree (components, `/usr/lib/modules` for the release kernel, factory defaults, shipped sysupdate transfers; kernel/initramfs in the UKI on the ESP, `/etc` via `/var/lib/etc`, `/var` + `/home` separate partitions); `usr-x86-64` type, versioned label `ingot_<v>` / `_empty`, A/B = two newest versions (`InstancesMax=2`); minimal tmpfs runtime root - initramfs mounts `/var` + `/etc` bind + slot ro at `/usr` (PARTUUID from the UKI cmdline) before switch-root, systemd mounts `/home` `/efi` `/tmp` at `local-fs`; sysext layers on top of the slot, extensions live in `/var` and persist across slot switches.
- [Lock the slot filesystem (erofs)](https://github.com/classy-giraffe/Ingot/issues/4): locked - erofs with zstd compression (kernel `CONFIG_EROFS_FS_ZIP_ZSTD=y` verified); erofs-only pipeline (ext4 stays an unimplemented MAY in the spec); the pre-built whole-image artifact `ingot_<v>.root.erofs` -> block device is the single write path, shared by the installer (both partitions; second slot `_empty` pre-staged as fallback) and sysupdate; erofs-utils from rawhide's tools tree; erofs module in the initramfs (non-hostonly dracut).
- [Lock the /etc persistence mechanism (bind mount over /var/lib/etc)](https://github.com/classy-giraffe/Ingot/issues/5): locked - `/var/lib/etc` a plain rw dir on `/var`, `/etc` a bind mount (initramfs, before PID 1); factory defaults in the slot at `/usr/share/factory/etc`; installer populates `/var/lib/etc` in phase 6; shipped idempotent oneshot - empty -> full factory copy (incl. `/usr/share/factory/var`), version change -> new-files-only merge (rpm `%config(missingok)` semantics, never clobbers); confext composes on top via the standard mechanism.
- [Lock the first profile (workstation)](https://github.com/classy-giraffe/Ingot/issues/6): locked - workstation v1 = btrfs `/var` + `/home` (subvolumes; `/var` snapshots = state rollback alongside A/B); SSH on by default; homed off for v1; full `linux-firmware`; updates admin-initiated (sysupdate timer off); package set = 7.1 core (no e2fsprogs) + all five Rust components + PAM/shadow/run0/openssh (no sudo-rs, no nftables); services = core systemd set + persistent journal + getty + sshd; dev tools (git) via sysext, not in the base slot.
- [Lock the installer modes (interactive + declarative)](https://github.com/classy-giraffe/Ingot/issues/7): locked - one execution engine, two input front-ends: the declarative config is the source of truth (all 11.4 categories); interactive = wizard that writes the config + confirms (11.6.2) then runs the same engine; declarative = non-interactive, config is the authorization (no confirm flag); Rust installer orchestrates repart (`.repart` definition with FIXED partition UUIDs), mkfs, whole-image deployment (#4), direct `/var/lib/etc` writes (#5), bootctl; ukify at release build time (fixed PARTUUIDs in the UKI cmdline, foobarOS pattern); firstboot N/A on /usr-only; logs to the target's `/var`.
- [Lock the test venue (QEMU+OVMF on this workstation, CI later)](https://github.com/classy-giraffe/Ingot/issues/8): locked - raw QEMU (10.2.1, KVM) harness scripts in the repo, no libvirt; **Secure Boot from day one via the edk2 snakeoil test key** (v1 signs loader + UKIs with it; production key management stays fog); install via config-disk auto-trigger (spec addition to Section 10); artifacts via the host's HTTP server over QEMU user-net; bare-metal install = manual milestone after QEMU is green; CI-mirror contract locked now (repo-contained, version-pinned, machine-independent, machine-readable results), execution deferred.
- [Lock the repo layout (single repo)](https://github.com/classy-giraffe/Ingot/issues/9): locked - single repo holds everything: `image/` = mkosi resources dir (conf, scripts, drop-ins), `repart/` = fixed-UUID `.repart` definitions, `src/` = Cargo workspace (members installer + update-helper, `ingot-*` binaries, no premature shared crate), `harness/` = QEMU harness, `docs/` = spec + agents + research (research branches merged into main), `.github/workflows/` reserved for the CI mirror (#8 contract).
- [Lock the update source (GitHub Releases via systemd-sysupdate)](https://github.com/classy-giraffe/Ingot/issues/10): locked - GitHub Releases the sole update source (no paid hosting; <2 GiB per asset): fixed asset set = `root.erofs` + UKI + live ISO + `SHA256SUMS`(.gpg) + `manifest.json`(.gpg); production transfers in `/usr/lib/sysupdate.d` (partition target, versioned labels, `InstancesMax=2`) + dev/test provider in `/var/lib/sysupdate-cache`; `ingot-update-helper` (`src/update-helper`) = API-based latest discovery (highest semver non-prerelease) + manifest auth + per-tag URL pin into `/run/sysupdate.d`; long-lived project GPG key (public key ships in the slot's vendor keyring); full firmware stays in the base with a hard 2 GiB build assertion (revisit at 1.5 GiB); publish gate = green harness, releases immutable.
- [Lock the server profile firewall policy (declarative nftables)](https://github.com/classy-giraffe/Ingot/issues/13): locked - input/forward default drop, output accept; default inbound surface = loopback + conntrack + tcp/22 from the `ingot_admin_src` set (empty = all sources; key auth is the gate) + icmp echo-request; one native `.nft` factory default at `/usr/share/factory/etc/nftables.conf` (#5 mechanism), loaded at boot by the distro `nftables.service`; host overrides persist and are never clobbered (new-files-only merge); server build adds nftables + the service, v1 workstation unaffected.

## Not yet specified

- The installer's declarative config file format (hangs on "Lock the installer modes").
- UKI and boot-entry details: loader entry ids, loader.conf default, bless-boot wiring, boot-attempt counter policy (Section 12 prescribes the shape; sharpened at implementation planning).
- Appliance profile decisions (in scope per destination; not yet sharp).
- Extension and OCI integration details: sysext governance, Quadlet-style unit definitions.
- LUKS/TPM2 protection and production Secure Boot key management (deliberately deferred fog; the v1 Secure Boot test path uses the edk2 snakeoil test key per #8, so real PK/KEK/db provisioning stays open).
- Compose archive storage and mechanism: where pinned Koji composes are archived (local disk vs NAS) and which compose subset is mirrored (full Everything vs minimal set) - build-ticket implementation detail.
- Spec revisions pending at the to-spec handoff: 7.1 add static dash as OPTIONAL initramfs shell; 8.2 slot mountpoint `/usr` + versioned labels (not `os-slot-a`/`b`); 12.2 versioned UKI names with the boot-counter scheme (not `os-slot-{a,b}.efi`); 9.2 immutable `/usr` model now normative; Section 10: the live ISO MAY auto-run the installer from a declarative config disk (unattended deployment, #8).
- erofs mkfs parameters (block size, compression level, global vs per-file): build-ticket implementation detail, recorded in build metadata (spec 20.4).

## Out of scope

- GUI and desktop stacks (Section 4 non-goal: no Wayland, X11, or desktop application stacks).
- The build itself: `/to-spec` → `/to-tickets` → `/implement` territory. This map stops when the way is clear.
